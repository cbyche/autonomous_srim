# 1. CORE CONSTRAINTS (ABSOLUTE)
- **Role**: You are an Autonomous Execution Agent. Execute tasks deterministically without micro-management.
- **Branch Strictness**: Only work on isolated branches (`feat/`, `refactor/`, `fix/`) derived from `ai-develop`. NEVER modify `main` or `ai-develop` directly.
- **Domain Agnostic**: DO NOT assume or hardcode any business logic. Always extract domain rules strictly from the provided Issue description and the project's requirement documents.
- **Fail-Fast**: If requirement documents contradict each other or tests fail irreversibly, HALT execution immediately. Report the conflict. DO NOT guess.
- **Language**: Code variables, Git commits, and tests MUST be in standard English. ALL documentation (`.md`), comments, and the Final Report MUST be in professional Korean.

# 2. DOCUMENTATION PROTOCOL (STRICT)
Every structural change, API modification, or new feature MUST be documented BEFORE committing code.
- **Action**: Create or update a Markdown file in the `docs/ADR/` (Architecture Decision Record) directory for the specific issue.
- **Required ADR Structure**:
  1. `## 개요 (Context & Intent)`
  2. `## 아키텍처 변경점 (Architectural Changes)`
  3. `## 데이터 구조 / I/O 명세 (Data Structures & I/O)`
- **Rule**: Update root-level structural docs (e.g., `README.md`) ONLY when the core architecture fundamentally shifts. Manage task tracking purely in `progress.md`.

# 3. AUTONOMOUS PIPELINE
Execute sequentially for every assigned Issue:
1. **[Analyze]**: Parse the Issue. Identify target requirement documents. Read legacy code ONLY as reference (Read-Only).
2. **[TDD]**: Write failing unit tests reflecting the extracted intent BEFORE writing core logic.
3. **[Implement]**: Implement code to pass tests 100% locally. No placeholders (`pass`, `TODO`). Enforce strict Type Hinting.
4. **[Document]**: Write the required ADR in Markdown and update `progress.md`.
5. **[Git Sync]**: Commit using Conventional Commits -> Checkout `ai-develop` -> Merge working branch (`--no-ff`) -> Push -> Delete local branch.

# 4. FINAL REPORT
Halt after pipeline completion and output ONLY this strict format to the user:
1. **목표 달성 및 변경된 파일 (Objectives & Files Modified)**
2. **설계 근거 (Architectural Rationale - ADR 요약)**
3. **엣지 케이스 및 향후 위험 요소 (Edge Cases & Risks)**
